## 2026-07-24 — Exhaustive vocation coefficient fixture + drift gate

**Problem.** Aggregate vocation-count checks and core Monk coefficient fixtures
existed, but nothing proved that *every* pinned progression coefficient of every
vocation is either matched or explicitly marked non-gameplay. A drifted number
(or a newly added coefficient) could slip through.

**What changed.**

- `tools/buildVocationCoefficientFixture.mjs` (new) — transcribes the pinned
  Canary `vocations.xml` (commit `a879c9312e34`) into
  `server/src/progression/vocationCoefficientFixture.json`: per shipped vocation
  (the internal "None" is skipped), every gameplay coefficient mapped to the
  project field names — `numericId`, `gains`, `regeneration` (with the engine's
  implicit `soulAmount: 1`), `maxSoul`, `attackSpeedMs`, `baseSpeed`,
  `magicProgressionMultiplier`, `skillProgressionMultipliers` (skill ids 0–6 →
  fist…fishing), and `formulas` (formula + mitigation groups). Canary XML is
  never loaded at runtime; this is a build-time transcription regenerated by
  running the tool against the pinned checkout (deterministic — re-running
  produces a byte-identical file).
- `server/src/progression/vocationCoefficientFixture.json` (new, generated) —
  the pinned fixture, 10 vocations.
- `server/src/progression/vocationCoefficients.test.ts` (new) — for every
  vocation in `VOCATION_DEFINITIONS`: (1) deep-equals the gameplay-coefficient
  subset against the fixture (any drift fails), and (2) asserts every top-level
  field is classified as gameplay (fixture-checked) or explicitly non-gameplay
  (`id`, `baseVocation`, `promotedFrom`, `promotedVocation`, `starter`,
  `client`) — a new unclassified field fails. Also asserts the fixture covers
  exactly the shipped vocation set.

**Files touched.** `tools/buildVocationCoefficientFixture.mjs` (new),
`server/src/progression/vocationCoefficientFixture.json` (new, generated),
`server/src/progression/vocationCoefficients.test.ts` (new).

**Verification.** `yarn workspace server test run
src/progression/vocationCoefficients.test.ts` → 21 passed (fixture matches all
10 vocations, all fields classified). Re-running the generator yields no diff.
`yarn workspace server typecheck` clean.

**Delegated (still open, per the feature plan).** Vocation PvP coefficients
(`<pvp>` in the XML) are Todo 15 / Feature 60 — they are not in
`vocationDefinitions.ts` yet, so they are intentionally absent from this fixture;
add them here when Feature 60 lands. Gem/Wheel coefficient families are Todo 16
(Features 79–82, notably 81).

**Residual risk.** None. If a coefficient is legitimately retuned, regenerate
the fixture (`node tools/buildVocationCoefficientFixture.mjs`) in the same PR;
the test will otherwise flag the drift.
