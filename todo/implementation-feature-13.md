# Feature 13 — Trash holders

Part of [Todo 6 — Items and inventory](todo-6.md).

## Why

79 catalog types carry `kind: "trashholder"` (dustbins, sewer grates, water/lava/tar tiles). In Canary, items dropped or thrown onto them are destroyed with an effect; here they currently just land on the tile.

## Remaining work

- An item dropped or thrown onto a trashholder tile must be destroyed with the appropriate effect plus an audit entry.
- Constraint (recorded 2026-07-20): trashholder-typed liquids (water/lava/tar) are static map scenery — there is no world item on the tile to inspect, so the behavior must key off the catalog type of the destination tile at throw time, not off a world item.

## Implementation

- Hook the destination check into `/home/randal/code/tibia/server/src/item/plan/planDrop.ts` and `/home/randal/code/tibia/server/src/item/plan/planMoveMapItem.ts`.
- Catalog-type lookup via `/home/randal/code/tibia/server/src/item/ItemCatalog.ts` and `/home/randal/code/tibia/content/canary-item-semantics.json` (generated by `/home/randal/code/tibia/tools/getMapItemSemantics.mjs`).
- Destruction is an audited economy event: write to the audit log via `/home/randal/code/tibia/server/src/item/PgItemAudit.ts` in the same transaction that destroys the item (charter rule 11); destruction itself is a single atomic operation (charter rule 2).
- Canary reference: `Tile::hasFlag(TILESTATE_TRASHHOLDER)` / trashholder handling on item throw.

## Tests

- Drop onto a dustbin destroys exactly once, with exactly one audit row.
- Concurrent drop races onto the same trashholder leave zero items and no duplicate audit entries.

## Dependencies

- None; standalone. Feeds Feature 17 (item-parity gate).
