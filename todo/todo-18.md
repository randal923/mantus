# Todo 18 — Operations, observability, and security

Partially shipped (see [done](done.md)): `PROTOCOL_LIMITS` message-size and message-rate enforcement is live (`protocol/src/limits.ts`, `GameServer.ts` `maxPayload`, per-connection rate window in `Session.ts`); a DEV_COMMANDS-gated moderation suite (kick/ban/mute with same-transaction `moderation_actions` audit rows and immediate live-session kick) exists in `server/src/moderation/`; economy audit rows are written in-transaction; and two load-test baselines exist (4,000-player protocol capacity, 1,900-monster hotspot gate — both explicitly insufficient as launch gates). Everything else is not started: the server still logs via `console.*`, there are no metrics, no drain/shutdown path, no typed error categories, no backups/reconciliation automation. Ordering: Features 93 (network/resource limits) and 97 (server error handling) protect the live game and should land earliest. Feature 96's role-column migration plus session gate is a small change that simultaneously closes gaps in todo-19 (instant-ban role gating) and todo-20 (per-account GM gating). Feature 100 is the final pre-launch gate and assumes Features 93–99 plus Feature 1's parity-ledger closure.
